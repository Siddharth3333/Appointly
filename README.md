# Appointly (free-tier deployable)
Flask + SQLAlchemy/Alembic + vanilla-JS UI served by the same Flask service. Render Free + Supabase Free + Resend Free + GitHub Actions cron.

## Project layout
`app.py` Flask API + serves the UI; `frontend/` React + Vite + TypeScript + Tailwind + Recharts + Lucide (login, dashboard, appointments); `static/index.html` the classic UI, still serving the public `/book/<slug>` and `/manage/<token>` pages and the remaining admin screens at `/legacy` (calendar, clients, services, availability, analytics, reminders log, settings).

## Run locally
React dev (hot reload): in one terminal `flask run`, in another `cd frontend && npm install && npm run dev` (proxies /api to :5000).
Production-style: `cd frontend && npm install && npm run build`, then `flask run` serves the built app at /.

(Original steps:)
    pip install -r requirements.txt
    cp .env.example .env          # leave DATABASE_URL empty to use SQLite
    export FLASK_APP=app.py && flask db upgrade && flask run
Open http://localhost:5000, register, add a service, then visit /book/<your-slug>.

## Deploy ($0)
1. **GitHub**: create a repo, then `git init && git add . && git commit -m init && git remote add origin <url> && git push -u origin main`.
2. **Supabase**: new project → Project Settings → Database → Connection string → *Session pooler* (URI). Replace `[YOUR-PASSWORD]`. This is `DATABASE_URL`.
3. **Resend**: sign up → API Keys → create key = `RESEND_API_KEY`. Without a verified domain, Resend only delivers to your own account email (use `onboarding@resend.dev` as sender while testing).
4. **Render**: New → Blueprint → pick your repo (reads `render.yaml`, Free plan). Set `DATABASE_URL`, `RESEND_API_KEY`, and `APP_URL` (your `https://<name>.onrender.com`). Migrations run on every start. Copy the generated `CRON_SECRET` from Render's Environment tab.
5. **GitHub Actions**: repo → Settings → Secrets and variables → Actions → add `APP_URL` and `CRON_SECRET`. Actions tab → *process-reminders* → Run workflow to test.
6. **Test**: register, create service, book via `/book/<slug>`, check *Reminders log*. Open `/healthz` to check the DB connection.

## Limits of free tiers (read this)
- Render Free sleeps after ~15 min idle: first request takes ~30-60 s. The 10-minute cron also keeps it mostly awake, but GitHub may delay or skip scheduled runs, so reminders can arrive late. Not real-time.
- Supabase Free pauses projects after ~1 week of inactivity (the cron traffic counts as activity but don't rely on it); restore from the dashboard.
- Resend Free has daily/monthly send caps and domain restrictions.
- Reminders are idempotent: a unique (appointment, kind) row, row locks, per-row commits, up to 3 attempts.

## Troubleshooting
- 503 on /healthz: wrong `DATABASE_URL` (use the pooler URI, `sslmode` not needed).
- Reminders log shows `RESEND_API_KEY not set`/`Resend 403`: fix key or sender domain; failed rows retry on the next run (max 3).
- Workflow returns 403: `CRON_SECRET` mismatch between Render and GitHub.

## Added since v1
Calendar (FullCalendar month/week/day/agenda, drag-to-reschedule, click-to-create, service/status filters), analytics page (Chart.js, date ranges), blocked time/holidays, CSV export/import, dark/light toggle.

## Also added
Per-day break periods (public slots skip them), CSRF tokens (`X-CSRF-Token` header, issued at login), database-backed rate limiting (login, sign-up, public booking; survives restarts), global search (Enter in the top bar), alerts bell with failed-reminder count, client profile pages (notes, upcoming, history), appointment edit dialog.

## Not implemented / caveats (honest list)
Only login, dashboard and appointments are in React so far; the other admin screens and the public booking page are still the classic UI. shadcn-style components are hand-written (`.card`, `.btn`, `.input` in index.css), not generated by the shadcn CLI. Render's Python runtime should have Node for the build step, but I could not test a Render build; if it fails, run `npm run build` locally, remove `frontend/dist/` from .gitignore and commit it.

(Earlier notes:)
The UI is vanilla JS, not React/Vite/TypeScript/Tailwind/shadcn, and charts use Chart.js instead of Recharts. Admin-created appointments ignore weekly hours and breaks (only conflicts and blocked time apply). Calendar and charts load from the jsDelivr CDN.
